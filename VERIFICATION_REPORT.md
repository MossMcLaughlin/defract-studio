## Build and automated tests

Color-engine Checkpoint 2 and the Checkpoint 1 persistence gap were implemented on 2026-11-03. New imports store ImageIO photo or CoreMedia video source-color evidence in the recipe and persist it through reload and same-source undo/redo; relinking re-probes the replacement. New recipes use schema/renderer v2, while old recipes with absent renderer version remain on v1 without migration. An immutable render plan is shared by photo/video preview and export. V1 retains its previous sRGB context and render path; v2 uses an extended-linear-sRGB RGBAh context with an explicit sRGB photo preview/export destination. V2's new technical stages are neutral and its creative math remains v1 for now. The focused version, neutral-render, import-persistence, relink-undo, and 8/10-bit SDR fixture tests passed. Neutral v1/v2 photo previews matched in encoded sampled pixels (mean RGB difference below 0.001), but v1's device-RGB preview and v2's tagged sRGB preview produced different values when converted through the display profile; this is a color-management difference, not a new grade. No visual color-quality improvement is claimed. HDR/Log normalization, new color math, protection, visibility, export precision, performance measurement, and human grade evaluation remain for later checkpoints. Video metadata is probed asynchronously; a preview can start before that evidence is stored, and unsupported HDR is blocked once its transfer is identified. No macOS 15 runtime or HDR/Log fixture was available for this checkpoint.
