# Development notes

`EditorApp.xcodeproj` has one macOS app target (`EditorApp/`), one portable framework (`EditorCore/`), and one XCTest target (`EditorTests/`). `EditorApp/App.swift` is the entry point. The target is macOS 15+ on Apple Silicon. Local Debug builds are unsandboxed and need no external package; sandboxed distribution would require security-scoped source bookmarks, signing, and further testing.

## Where behavior lives

| Concern | Current source |
|---|---|

| Versioned color math, source protection, spatial visibility, output detail/dither and shared Core Image rendering | `EditorCore/ColorMath.swift`, `EditorCore/ColorMathV3.swift`, `EditorCore/ColorGradeV3.metal`, `EditorCore/NoiseProtection.swift`, `EditorCore/NoiseProtectionV4.metal`, `EditorCore/VisibilityV5.swift`, `EditorCore/VisibilityV5.metal`, `EditorCore/OutputV6.swift`, `EditorCore/OutputV6.metal`, `EditorCore/Core.swift` |
| Bounded still/video source noise and water analysis | `EditorApp/SourceNoiseAnalysis.swift` |
| Source-aligned masks, inverse copy, radial angle, ordered local blending | `EditorCore/Masks.swift` |
| Crop/rotation and Fit/Fill output framing | `EditorCore/Geometry.swift`, `EditorCore/OutputFrame.swift` |
| Atomic JSON project storage and bounded undo/redo | `EditorCore/ProjectStore.swift` |

`EditRecipe` is the only saved edit description. Easy changes recompute base contributions; Advanced writes a delta relative to the base; the renderer receives effective values. A slider drag edits a transient draft and commits one history transaction on release. Local masks use the same Advanced parameter definitions without Easy bases. Enabled masks process in saved order after the global grade. Brush strokes and optional Vision matte remain in source coordinates through preview zoom, crop, and export. An inverse copy clones the editable selection definition with a new ID and neutral local grade; `rotationDegrees` is optional so older mask JSON decodes at zero angle.

Renderer v1 is retained for schema-1 projects, including recipes whose optional `rendererVersion` is absent. Saved v2/v3/v4 projects keep their prior paths and Easy mapping v1; v5 keeps Easy mapping v2. New imports use schema/renderer v6 and Easy mapping v2. `RenderPlan` snapshots the recipe for photo and video preview/export: v5 optionally protects the interpreted source, applies Global Dehaze, unchanged v3 creative color, Global Clarity, then saved-order local edits and local Clarity before geometry/output framing. V6 adds optional Sharpening after output framing. `MediaIO` owns color conversion: v1 keeps its existing sRGB CIContext; v2–v6 use extended-linear-sRGB RGBAh with an explicit sRGB photo destination. ImageIO photo evidence is stored at import; asynchronous CoreMedia video evidence is saved without creating an undo edit. Recorded HDR transfer evidence blocks v2–v6 preview/export pending a verified normalization path. Existing saved recipes are not migrated.

V4's optional `technicalDetail` and `noiseAnalysis` fields decode absent for old projects. Analysis runs off the UI thread after source interpretation, using one upright still or three deterministic trimmed video frames; the overview selects native-resolution tiles, and only compact noise proxies/confidence are saved. Identity includes source path, file size/mtime, color interpretation, trim and estimator version. Selection, source or trim changes cancel/invalidate work; a late result cannot overwrite a new draft. Analysis metadata does not create an undo step and is propagated across compatible undo states. Detail changes do create normal undo transactions; Reset All restores v4 Detail defaults while retaining source interpretation. A future Copy All operation should copy explicit Detail settings but not source-specific analysis. No Copy All command currently exists. The source-protection stage returns the exact CIImage at zero demand and otherwise uses one masked demand field and one Metal bilateral pass before creative grading. The current tile/video estimator is a conservative proxy; AVAssetImageGenerator may deliver an 8-bit analysis image from a 10-bit clip, while the actual grade still uses the managed source frame. See measured costs and quality limits in `VERIFICATION_REPORT.md`.

V5 adds an optional water-color/confidence record to the same persisted analysis snapshot. The new analysis identity version forces recomputation for v5 recipes, and one video snapshot spans three fixed points in the selected trim. The estimator uses a 1024-pixel ungraded overview and robust smooth blue/green candidates; ambiguous scenes reduce Dehaze through confidence. Clarity uses a reduced log-luminance source with Core Image's guided filter and a bounded Metal detail response; Dehaze uses a small source blur and bounded scalar transmission, both using the existing shared CIContext. Slider changes do not repeat scene analysis. Global Dehaze is intentionally absent from mask controls; local Clarity runs before the saved mask blend. These spatial coefficients and the v2 Visibility knots are initial estimates. The v5 path performs no new spatial work at Clarity/Dehaze zero; v4 Auto protection may still run when its existing grade demand is positive.

V6 keeps v3–v5 creative processing unchanged. Advanced Detail adds 0–100 Sharpening, default zero; older Detail JSON decodes the missing field as zero and old renderer versions ignore it. A luminance-only Metal response uses a 0.85-output-pixel Gaussian, measured luma-noise threshold and bounded overshoot after crop/resize; zero bypasses that work. The output Metal kernel adds deterministic triangular dither in encoded sRGB before photo 8-bit conversion, or an encoded-luminance approximation before AVFoundation's video-range YCbCr conversion. The seed uses output pixel coordinates for stills and nominal frame index for video; 10-bit video receives one-quarter the 8-bit amplitude. This is not control of the framework's final YCbCr quantizer. V6 video composition requests Rec.709 primaries, transfer and matrix together and renders through a Rec.709-output CIContext. Temporary exports are reopened to check photo 8-bit sRGB, video Rec.709 tags, and actual 10-bit HEVC for a 10-bit HEVC source before committing. Unsupported Main10 output produces an actionable error; it does not silently relabel an 8-bit file. The export sheet chooses HEVC for the Maximum Quality video preset on v6 recipes; users can still select H.264. Measured output comparisons and limits are in `VERIFICATION_REPORT.md`.

Explicit `.defractproject` files are versioned JSON documents containing ordered current histories and selected media ID; transient undo stacks are rebuilt on open. Atomic writes leave original media external. New unsaved projects live in memory until Save; an older implicit `ProjectStore` session is offered as an unsaved recovered project and its legacy JSON files are retired only after successful save or deliberate discard. New/Open cancel prior preview, analysis, subject and source-probe work before changing workspaces. Missing source records stay in the document but are filtered from the sidebar; opening presents one dismissible list. File > Delete Project moves only the active project document to system Trash and clears the workspace after success. The current unsandboxed build stores absolute source paths, without claiming sandbox bookmark support.

`ProjectStore` keeps legacy edits and history in `~/Library/Application Support/PhotoVideoEditor/Projects/`. Corrupt legacy JSON is left on disk while other histories recover. Preview images/caches are disposable. Legacy sessions retain per-file autosave; explicit projects save on user command or through the Save choice during a transition. Failed writes leave the active workspace intact and show an error.

`MediaIO` adapts photos and video to one `CoreRenderer` grade and geometry path. Photo preview uses a cached downsampled source (900 pixels while dragging, 1800 when idle); cancellation and revision checks prevent stale frames from publishing. Full-resolution photo export reopens the source. For v6 playback only, the video composition scales the decoded source before spatial grading to at most 1920 pixels on its long edge, and caps a larger selected output frame proportionally. This reduces spatial-filter work during playback while retaining the same grade, geometry and masks; video export still grades the full source and uses the requested frame. Older renderer versions retain their original composition size. Video updates the existing player's item composition on edit; preview and export use the same macOS 15-compatible `AVMutableVideoComposition.videoComposition(with:applyingCIFiltersWithHandler:completionHandler:)` handler. The macOS 26-only initializer is not used. Renderer v1/v2 use the original cached 33³ color cube and native temperature/tint. Renderer v3 uses a bundled Core Image Metal kernel for exposure, tone, Oklab mixer/colorfulness, and the SDR gamut boundary; a native temperature/tint filter precedes it. Its 4096-sample tone and 1025-sample wrapped mixer tables are cached by adjustment values, not rebuilt per video frame. `EditorCore` requires Xcode's Metal Toolchain and `-fcikernel` compile/link flags. These are initial photographic formulas, not Lightroom parity; measured video export cost and remaining visual evaluation are in `VERIFICATION_REPORT.md`.

Photo JPEG/PNG exports are 8-bit sRGB; video MP4 delivery is Rec.709 SDR with source audio preserved when present. The supplied `GX011247.MP4` is HEVC Main 10 **SDR**. V6 HEVC export from this source was decoded and verified as 10-bit; H.264 remains the 8-bit compatibility option. Both photo and video exports write a sibling temporary file, validate readable output, then move/replace only on success. `ExportOptions.swift` defines preset dimensions and formats. The export sheet temporarily previews the chosen output frame; its completion UI clears on a fresh sheet or source switch. No RAW-specific workflow or HDR mastering is promised.

Fit uses black padding to retain the entire cropped source at the requested output aspect; Fill crops overflow without stretching. Preview and export use the same framing operation. The older reference architecture's proposed nested source folders and package-style project schema were illustrative; the actual flat target folders and one JSON history file per media item are the maintained implementation.

The workspace uses a narrow collapsible sidebar, a central media canvas, and a 340-point right inspector. `EditorTheme`, `EditorTabs`, `InspectorSliderRow`, and `GoldSliderTrack` in `EditorApp/App.swift` hold shared UI styling; `EditorApp/MaskInspector.swift` reuses it. The slider modifier overlays a non-interactive sand fill on the native control because `.tint` alone left the active track gray on the tested macOS build. Ranges crossing zero fill outward from zero; minimum-based controls fill from the left; mixer Hue shows adjacent colors in the track. Both inspector scroll views keep 28 points of trailing content clearance. The stronger mask tint in `EditorApp/MediaIO.swift` applies only to preview when Show Mask Overlay is enabled, never to export. Radial rotation is shown in the equivalent ±90° range without rewriting older saved angles. The preview footer reads display-oriented dimensions from the selected source metadata. The approved direction is in `UX_SPEC.md` and `reference/STYLE_GUIDE_v0.1.md`; `reference/UI_REFERENCE.png` is a concept, not an app screenshot. See `VERIFICATION_REPORT.md` for tested results and open checks.
